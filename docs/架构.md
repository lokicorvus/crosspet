# CrossPet 架构

给想改代码的人看：代码分几层、每层管什么、加新功能该放哪。改之前先读一遍，能少走很多弯路。

## 一条消息怎么变成她的一个动作

```
AI 工具（Claude Code / Codex / DeepSeek Harness / Antigravity / Hermes / ZCode / WorkBuddy / Qwen Code……）
   │  ① 接入层：钩子 / 插件 / mod，把 AI 的事件翻译成「动作状态」
   ▼
状态目录（macOS：/tmp/crosspet，Windows：%LOCALAPPDATA%\CrossPet\state）
   │  <角色>-state.json、<角色>-sessions.json、<角色>-quota.json、<宿主>-host.json、seen-<AI> ……
   ▼
② 外壳：macOS 的 Swift / Windows 的 C#，每 0.3 秒看一眼状态文件有没有变，变了就交给网页
   ▼
③ 网页层：app/web，两端共用一份，决定演哪个动作、说什么台词、画什么特效
```

## 每层管什么

| 层 | 在哪 | 管什么 | 不管什么 |
|---|---|---|---|
| ① 接入层 | `integrations/`（`crosspet-hook.py` 是大部分 AI 共用的钩子脚本；`claude-code/mod`、`deepseek/dsh-plugin-crosspet`、`hermes/crosspet` 是各家的插件） | 把 AI 的事件翻成 `{pose, event, tool, ts}` 写进状态目录；按模型名选角色 | 不读对话内容、不读凭据；不决定动画怎么演 |
| 接入工具 | `tools/integrate.py`（两端共用；Windows 用随包的 Python 跑） | 把接入层装进 / 撤出各家 AI 的配置；诊断（反馈里的「接入诊断」） | 只动 CrossPet 自己写的那几行（见下面的规矩） |
| ② 外壳 | `app/mac/*.swift`（macOS）、`app/windows/src/*.cs`（Windows），两端按功能分文件、名字一一对应（比如贴边：`App+Dock.swift` ↔ `Pet.Dock.cs`） | 只管系统接口：窗口、透明和点击穿透、托盘 / 菜单栏、全局快捷键、全屏检测、读文件、起进程、设置窗口、一键更新 | 尽量不做「判断」——判断写在这里就要写两遍 |
| ③ 网页层 | `app/web/index.html`（桌宠）、`effects.js`（特效）、`codex-quota.js`（GPT 额度排版）、`quota-aggregate.js`（额度合并显示的排版）、`stand-in.js`（自定义角色响应其他 AI 的事件：她响应哪些 AI）、`codex-resets.js`（Codex 重置提醒：接口数据怎么分档、要不要说）、`peak-hours.js`（峰谷时段：各家规则、时间条、按时段换衣服的判断）、`whats-new.js`（「新功能」：每版的新功能文案，更新后的卡片和设置页都用它）、`text-size.js`（文字大小：锁定规则和画布尺寸）、`plugin-update.js`（插件更新提醒：要不要提醒、说什么）、`settings.html`、`feedback.html`、`devconsole.html` | 所有「判断」：收到什么事件演什么动作、多会话、甩她红温、额度怎么显示、什么时候算 reset、台词 | 不直接碰系统 |
| 角色 | `characters/<角色>/`（立绘 `*.webp` + `character.json`） | 立绘、台词、角色专属设置 | — |

外壳把东西交给网页，靠调网页里的全局函数（`applyCharState`、`setQuota`、`setCodexQuota`、`setSessions`、`setPageHidden`、`setSizes`……；`setSizes` 的返回值是网页算好的画布尺寸，外壳照着设窗口）；网页要外壳做事（设置窗口里的开关、反馈里的发送），靠各自平台的消息通道（macOS 的 `webkit.messageHandlers`，Windows 的 `chrome.webview.postMessage`）。

## 加新功能先问：放哪层？

1. **要碰系统吗**（窗口、文件、进程、快捷键、托盘）？→ 那一小块放外壳，**两端都要写**，写薄一点
2. **其余所有判断**（什么时候、要不要、显示成什么）→ 放网页层，只写一份
3. **要从某个 AI 拿新信息**？→ 接入层多写一个字段进状态文件，判断还是在网页层做
4. 实在要在外壳里写判断（比如额度什么时候去问 Codex），在两端的代码里都注明「和另一端一致」，并在设计文档里写清规则

已知还在两端各写一份的判断（以后改到时优先挪进网页层）：GPT 额度的查询时机、贴边、心跳读取、检查更新的节奏、全屏隐藏的条件。

## 规矩

- **改别家的配置只删自己的。** 撤销 / 刷新接入时只移除 CrossPet 自己写的条目，用户自己的内容（哪怕夹在我们的条目中间）一行不动。改之前都备份。相关代码改动必须有测试覆盖「用户内容夹在中间」「重复执行」「格式不认识」三种情况（`tests/integrate_test.py`）
- **不碰凭据。** 不读 `~/.codex/auth.json` 这类登录文件；要用账号数据时让对方程序自己去查（比如 GPT 额度问 Codex 本地服务），CrossPet 只拿结果里的数字
- **注释写「为什么」**，尤其是绕开某个系统 / 第三方程序的坑时，写清楚坑是什么，免得以后有人「顺手清理」掉
- **两端都要改的功能，两端一起改、一起编译**（`app/build.sh`、`tools/build-windows.sh`）

## 记录（反馈用）

反馈按问题类型附信息（规则在 `app/web/feedback-plan.js`，设计见 `docs/superpowers/specs/2026-10-21-feedback-redesign-design.md`）。为此有三种记录，都只存在用户自己电脑上、只在发反馈时附上：

| 记录 | 位置（数据目录下） | 谁写 | 每行 |
|---|---|---|---|
| 钩子事件记录 | `events/<接入名>.jsonl` | `crosspet-hook.py`、DeepSeek Harness 插件、Claude Code mod | `{t, ev, tool, sid, turn, result, detail}` |
| 桌宠处理记录 | `events/pet.jsonl` | 两个外壳 | `{t, char, ev, pose, result, detail}` |
| 换角色记录 | `switches.jsonl` | 两个外壳（`switchTo` / `SwitchTo`） | `{t, from, to, skin, why, via}` |

- 接入名：`codex` `claude-hooks` `claude-mod` `deepseek` `antigravity` `gemini` `qwen` `workbuddy` `zcode` `hermes`
- `result`：钩子是 `shown` / `dropped` / `error`（`detail` 是「角色 姿态」、丢弃规则名或异常类名）；桌宠是 `played` / `skipped`（`stale` `paused` `front-ai` `answer-stale`）。网页自己的判断（不是当前角色、正在演彩蛋……）不写文件，在 `diagnoseDisplay()` 里
- `sid` 是会话 id 的哈希前 6 位，只用来分清几个会话
- 只留最近 200 行（超过 240 行时截回 200）；写不了就算了，不能影响钩子 / 插件 / 桌宠
- **绝不记**：prompt、工具参数和结果、AI 的回答、对话记录路径、工作目录、任何凭据
- 运行日志：Windows `%LOCALAPPDATA%\CrossPet\windows.log`，macOS `~/Library/Logs/CrossPet.log`，超过 1 MB 删掉重来
- 测试里调用插件 / 钩子时一律把数据目录指到临时目录（`CROSSPET_DATA_DIR` 或插件配置 `dataDir`），别往真实的数据目录写记录

## 测试

| 测什么 | 怎么跑 |
|---|---|
| 接入工具（改配置、诊断） | `python3 -m unittest tests.integrate_test` |
| 钩子读事件（不等输入关闭、超时、大事件） | `python3 -m unittest tests.hook_stdin_test` |
| GPT 额度排版（网页层） | `node --test tests/codex_quota_view.test.js` |
| 额度合并显示的排版（网页层） | `node --test tests/quota_aggregate.test.js` |
| 自定义角色响应其他 AI（网页层） | `node --test tests/stand_in.test.js` |
| Codex 重置提醒（网页层） | `node --test tests/codex_resets.test.js` |
| 峰谷时段（网页层） | `node --test tests/peak_hours.test.js` |
| 「新功能」卡片和设置页列哪些（网页层） | `node --test tests/whats_new.test.js` |
| 文字大小（网页层） | `node --test tests/text_size.test.js` |
| Gemini（Antigravity）额度排版 | macOS：`app/build.sh && tests/antigravity_quota_probe.sh`；Windows：`~/.dotnet/dotnet run --project tests/windows/LogicTests`（样本共用 `tests/fixtures/antigravity/`） |
| 换大小时窗口放在哪（macOS 外壳；Windows 同一套规则） | `app/build.sh && tests/window_place_probe.sh` |
| DeepSeek 余额汇总（插件，多币种） | `node --test tests/deepseek_balance.test.mjs` |
| DeepSeek 插件什么时候查余额 | `node --test tests/deepseek_plugin_poll.test.mjs` |
| 插件更新提醒（网页层） | `node --test tests/plugin_update.test.js` |
| GPT 额度查询（macOS 外壳，用假的 codex） | `app/build.sh && CROSSPET_CODEX_TIMEOUT=3 tests/codex_quota_probe.sh` |
| Windows 版 | 在 macOS 上只能编译（`tools/build-windows.sh`）；运行行为在 Windows 上实测 |

修 bug 时尽量先写一个能复现它的测试，修好后它就成了防止再犯的测试。

## 分支和发版

- `dev`：日常改动都在这里，测试版从这里发（GitHub Releases 上的 Pre-release）
- `main`：永远等于最新正式版。一键安装命令下载的 `get.sh`、README 都从 `main` 读
- 发正式版：`dev` 合并进 `main`，打 tag，发 Release（Mac 包 `CrossPet-macOS.zip`，Windows 包名 `CrossPet-Windows.zip` 不能改——一键更新按这个名字找）
- 欢迎提 PR，请提到 `dev`
