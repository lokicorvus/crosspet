# 两只桌宠同时在场 · 设计（第一期：基础显示）

日期：2026-10-19　状态：loki 已口头确认方向，待审阅本文
来源：很多用户反馈想要「多角色一起显示」，热闹一点（最常见的组合是 DeepSeek + GPT）；PR #20（@GongShun-123）做了 Windows 版「每个在干活的模型各一只」，没合并（只做了 Windows、默认开、按「干活」而不是「在线」）

## 为什么做

用的人常常同时开着两个 AI（DeepSeek Harness + Codex 最多）。现在只有一只桌宠，谁动就换成谁，看不出两边各自的状态。用户要的不是效率，是热闹：两个 AI 都在线时，两只角色都在桌面上。

## 目标（第一期）

- 两个 AI 都**在线**时，桌面上出现两只，各自一个窗口（loki 选的布局 B），各自跟着自己的 AI 做动作、显示自己的额度
- 最多两只（loki 定：稳定后再考虑三只）
- **默认关**，设置里打开；关着时走现有代码，行为不变（我的决定，压 bug 风险）
- Mac 和 Windows 一起做，判断写在网页层（`docs/架构.md`）

不做（第一期）：
- 两只之间的互动、双人立绘、小剧情（loki 定：基础跑通再想）
- 三只以上
- 按会话拆成多只（同一个 AI 开好几个对话，仍由那一只用现有的多会话卡片演）

反目标（做出来但算失败的样子）：
- 打开开关后，原来单只时的行为（拖动、贴边、点击、额度、彩蛋、更新提醒）出问题
- 第二只闪来闪去（程序刚开又关、事件断断续续时反复出现 / 消失）
- 两只抢着做「只该做一次的事」（换衣服发两遍、更新提醒说两遍、两张「新功能」卡片）

## 一、什么算「在线」

一个角色在线 = 下面任一条成立：

1. **它的程序开着**：Mac 用角色 `character.json` 的 `apps`（bundle id），Windows 用 `app/windows/apps.json`（exe 名 → 角色）；外壳查正在运行的进程
2. **最近有事件**：这个角色的状态（`<id>-state.json` 的 `ts`，或 `<id>-sessions.json` 里任一会话）在 **10 分钟**内更新过，且最后一个事件不是 `SessionEnd`（我的决定：命令行工具没有窗口，只能看事件；10 分钟和「卡住兜底」同一量级）

会按模型换角色的宿主（WorkBuddy、ZCode、Hermes、Qwen Code，以及 Claude Code、Codex、DeepSeek Harness——它们都写 `<宿主>-host.json`）：程序开着时，算**它最近一次用的模型对应的角色**在线，和桌宠现在按模型换角色的规则一致。比如 Codex 接的是 DeepSeek 的接口，那「Codex 开着」算 DeepSeek 在线、不算 GPT（我的决定，审阅时提出）。没有记录时：宿主名本身是角色（claude / gpt / deepseek / qwen）就算那个角色，有默认角色的（zcode → glm）算默认角色，都没有（比如 WorkBuddy 还没用过任何模型）就不算谁在线。

防闪：在线 → 不在线要持续 **30 秒**才算下线（我的决定）；不在线 → 在线立刻生效。

## 二、显示哪两只

- **主桌宠**：照现在的规则（跟随前台、跟随事件、手动选），一点不变
- **第二只**：在线、又不是主桌宠的角色里，最近有事件的那个；都没有事件就按程序打开的先后（先开的优先）
- 没有别的在线角色：只有主桌宠（和现在一样）
- **已经在场的角色固定在自己的窗口里**（我的决定，审阅时提出）：两只都在时，「跟随前台 / 跟随事件」要换成的角色如果已经是第二只，就不换（不然在 DeepSeek 和 Codex 之间切一次窗口，两只就对调一次、各「噗」一下）；要换成的是不在场的角色，才换主桌宠，第二只保持不动（它若因此不再是候选，按第二节重新挑）
- 手动从菜单选了第二只正在演的角色：两只对调（这是用户明确要的）
- 自定义角色写了 `reactTo`（替别的 AI 演）：被她代演的那些 AI 不当第二只的候选，免得同一个事件两只一起演（我的决定）
- 多模型宿主里认不出的模型写进 `current-state.json`：照旧交给主桌宠演
- 彩蛋角色、皮肤：第二只穿这个角色当前的衣服；彩蛋只由主桌宠演（第二只不演）

## 三、用户看到的

### 设置

「角色」页新开关，默认关：

> **在线的 AI 各显示一只**　同时开着两个 AI（比如 DeepSeek 和 Codex）时，桌面上出现两只，各自跟着自己的 AI 干活。最多两只

### 第二只出现 / 离开

- 出现：在它上次的位置（每个角色各记一个位置）；第一次出现放在主桌宠旁边、不重叠（左边放不下就放右边）；「噗」一下冒出来，说一句它的登场招呼（同现在 30 分钟冷却）
- 离开：说一句 `bye` 台词，「噗」一下消失

### 两只都在时

- 各自拖动、各自贴边（贴边状态也各记各的）、各自单击摸头 / 甩红温
- 各自显示自己的名字、额度（峰谷时间条跟着各自的角色）、多会话卡片、气泡；开了「合并显示各家额度」时，主桌宠显示合并的表，第二只不显示额度（免得同一家显示两遍，我的决定）
- 跟角色绑定的反应由演这个角色的那只来演：额度紧张时累了、登场招呼、认错。额度刷新的庆祝（GPT reset、DeepSeek 充值吃饭）由主桌宠页面判断（它独占额度记忆），判出来交给演这个角色的那只演（见第五节）
- 共用的设置对两只都生效：人物大小、文字大小、名字显示、光晕、显示层级、全屏隐藏、省电、隐藏快捷键（一次藏两只）
- 右键第二只：精简菜单（摸摸头、戳一下、让她先回去、设置…）；换角色、召唤彩蛋、会重置吗、更新、退出只在主桌宠的菜单里（我的决定：避免两个菜单互相打架）
- 「让她先回去」：第二只离开，这个角色在这次下线之前不再当第二只（下线再上线、或重启 App 后恢复）；不记到设置里

## 四、只该做一次的事（全部只在主桌宠的页面做）

按时段换衣服（`checkPeakOutfits`）、Codex 重置提醒的查询和主动说、插件更新提醒、「新功能」卡片、刚更新完的开心、彩蛋、检查更新、额度变化判断（`quotaEvent`，写 `crosspet-quota-memory`）。第二只的页面以「只显示」模式运行：这些一律不做。

原因之一：两个页面同源，**本机存储（localStorage）是共用的一份**（Mac 两个 WKWebView 同进程共用；Windows 也要求同一进程、同一个 WebView2 环境，见第五节），两页都写同一个记录就会互相覆盖。

## 五、程序分工

### 网页层

- 新纯函数模块 `app/web/companions.js`（node 测试）：
  - `online(now, apps, states, hosts, last)` → 在线角色列表（含 30 秒防闪，`last` 是上次的结果和下线开始时间）
  - `pickSecond(main, online, activity)` → 第二只的角色 id 或 null
- `index.html`：
  - 新的外壳调用 `setRole('main' | 'second')`：`second` 时关掉第四节那些
  - 主桌宠页面：收到外壳给的「正在运行的程序」和状态后算出第二只，`toShell({ second: id | null })`
- `settings.html`：「角色」页开关

### 两个外壳

- 设置 `twoPets`（布尔，默认 false）
- 主桌宠：照旧读状态文件、查额度；跟随前台 / 跟随事件换角色前先问网页（或按网页给的「在场角色」判断），已经在场的不换（见第二节）；另外定时（和现在的状态轮询同频）把正在运行的、能对应到角色的程序列表交给网页
- 收到 `{ second: id }`：开（或换角色）第二个窗口；`null`：关掉
- 第二个窗口：**和主桌宠同一个进程**里的另一个透明窗口 + 网页控件（Windows 共用同一个 WebView2 环境，不像 #20 那样按数据目录多开进程，和 Mac 保持一致，我的决定），加载同一个 `index.html`，`setRole('second')`；状态、额度由主桌宠转发（同 #20 的「控制者转发」思路：第二只不自己读文件、不建托盘、不查更新）
- 庆祝转发：主桌宠页面判出某个角色的额度事件、而这个角色正在第二只身上，就 `toShell({ celebrate: { id, ev } })`，外壳转给第二只的页面调 `celebrate`
- 位置 / 贴边按角色记（`position-<角色>` / `dock-<角色>`），单只时的记法不变
- Windows 可以参考 #20 的实现，用到的代码在提交说明和 CHANGELOG 里注明来自 @GongShun-123
