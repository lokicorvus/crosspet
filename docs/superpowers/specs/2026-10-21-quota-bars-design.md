# 额度条样式 · 设计

日期：2026-10-21　状态：loki 已确认方向（单家选 A「一行一条」，合并显示选 B「一家一行、每个额度一格」），待审阅本文；放 1.3.8
来源：有用户希望 Claude、GPT 这些套餐额度能像官方「Plan usage limits」那样显示成进度条；loki：就是多一个样式，作为可选

## 为什么做

现在额度在名牌下面显示成一行行文字（「5小时 剩余 91% ｜ 本周 剩余 59% · 10/26 重置」）。有人更喜欢一眼看长短的进度条。不是现在的文字不好用，只是多一种样式给人选。

## 目标

- 「设置… → 额度」里加一个二选一：**文字**（现在的样子，默认）/ **额度条**（loki 定：可选样式）
- 额度条长这样（loki 从三种里选了 A「一行一条」）：每个额度窗口一行，左边名字（5小时、本周……），中间一条，右边剩余百分比，**条后面用小字补一个短的重置时间**（loki 定）
- Mac 和 Windows 一起做；画法写在网页层

不做：
- 不改额度从哪查、多久查一次
- 不动 Codex 重置提醒那一行、峰谷时段（时间条 / 文字），它们照常显示在额度下面
- 不加第三种样式（比如截图那种上下两行的）

反目标：
- 选了额度条后，某家的额度不显示了、或显示成空条（认不出的要退回文字，不能丢信息）
- 额度条把人物往上顶太多（底栏有高度预算，见下）
- 默认样式下有任何变化（没选额度条的用户什么都不该察觉）

## 一、长什么样

一行：`5小时 ▬▬▬▬▬▬▬▭▭ 91%  3:40`

- **名字**：现在文字里的窗口名，原样用（5小时、本周、Gemini 本周、Claude/GPT……），宽度按内容，几行的名字左对齐
- **条**：长短 = **还剩多少**（我的决定：和现在文字写的「剩余」一致；官方界面画的是用了多少）。底色浅灰，条是蓝色；这一行快用完（剩余 ≤ 10%，和现在文字变红的门槛一致）时条和百分比变红
- **百分比**：剩余百分比，粗体
- 额度条样式下，整块额度框不再像文字样式那样变成红底（红只落在快用完的那一行上，免得整块都红看不出是哪一条，我的决定）
- **重置时间**：小字、浅色。24 小时内写「3:40」，7 天内写「周一」，再远写「10/26」（我的决定）。**每一行都写自己的**（现在的文字只在一两行上标，额度条有地方就每行都标）；没有重置时间的不写；已经过了重置时间、又没有新数据的窗口按现在的规则当满的（100%），不写时间
- GPT 额度用的是「最后一次读到的数」时，现在文字末尾会加「· 15:20 的数据」：额度条模式下在最后一行下面用小字照样写一行（我的决定）

## 二、哪些 AI 画成条

- **画成条**：有剩余百分比的——Claude（Claude Code 增强版 mod 推来的 5 小时 / 每周）、GPT（Codex 的 5 小时 / 每周）、Gemini（Antigravity 的各个额度池）
- **照旧显示文字**：DeepSeek（显示的是余额，钱数没有「满」）、其他没有百分比的
- **合并显示各家额度**开着时（loki 从两种里选了 B）：照现在合并显示的表格排，**一家一行、每个额度一格**，格子里是一根短条加剩余百分比，**不写重置时间、也不写窗口名**（5小时 / 本周），格子的先后和现在文字表格一致。高度和现在的合并显示一样，沿用现有的收紧（`tight`）和名字截短。没有百分比的那家（DeepSeek）在表里照旧是文字。快用完的那格条和百分比变红
- 只显示当前一家时，才是第一节那种每个额度一行、带名字和重置时间的样子
- 自定义角色写了 `reactTo` 替别家演时显示的额度表，规则同上

## 三、数据从哪来

现在三家交给页面的都只是一串文字，额度条要的是结构化的数：

- 每个额度对象（`setQuota(id, q)` 的 `q`）在 `text`、`low` 之外**加一个 `bars`**：`[{ label, left, reset }]`，`left` 是 0–1 的剩余比例，`reset` 是重置时刻（Unix 秒，没有就不写）。`text` 照旧给，文字样式和旧版本都用它
  - GPT：`app/web/codex-quota.js` 的 `view` 已经有 `windows`，在这里加
  - Gemini：Mac `App+Quota.swift`、Windows `AntigravityQuota.Parse.cs` 生成文字的地方顺便给
  - Claude：Claude Code 增强版 mod（`integrations/claude-code/mod/hooks/register.ts` 的 `quotaOf`）写 `claude-quota.json` 时加
- **没有 `bars` 时**（用户装的还是旧版 mod、或者别的来源）：网页层按现在文字的固定格式 `<名字> 剩余 N%` 拆出来画条，拆不出来的那一段照旧显示文字。拆字只是兜底（我的决定：不能因为 mod 没更新就显示不了）。拆字拿到的重置时间是现在文字里的写法（「3:40」「10/26」），原样显示，不换算成「周一」；文字里只有一两行带重置时间，其余行就不写（我的决定）
- 画法和拆字放网页层的纯函数（新文件或并进 `quota-aggregate.js`，实现时定），node 测试

## 四、高度

底栏（`#foot`）有高度预算：现在超了会先去掉峰谷时间条的刻度、再去掉时间条。额度条一行和一行文字差不多高（条 5px，和字并排），两个窗口大约 30px，不比文字高。合并显示四家时会更高。超预算时按这个顺序让步（我的决定）：先按现在的规则去掉峰谷时间条的刻度和时间条；还超就整体退回文字样式。原则是**不比文字样式更容易超**

## 五、设置

- 设置项 `quotaStyle`：`"text"`（默认）/ `"bars"`；两个外壳存取、启动时交给网页（`setQuotaStyle`），和 1.3.7 的 `peakStyle` 同一套做法
- 「设置… → 额度」加一行「额度显示样式」，两个按钮「文字 / 额度条」，说明里写：DeepSeek 余额照旧是文字
- 反馈里的运行状态加一项

## 六、测试

- 纯函数：给定 `q`（有 / 没有 `bars`）、现在时刻 → 每行的名字、比例、是否变红、重置时间短写；拆字兜底（标准格式、带「· 3:40 重置」、带「· 15:20 的数据」、拆不出来）；合并显示
- `codex-quota.js` 现有测试补 `bars`；Claude mod、Gemini 两端各补对应测试（Gemini Windows 进 LogicTests）
- 浏览器预览：文字 / 额度条两种，各家、合并显示、快用完变红；Mac 实测；Windows 由 Codex 跑一轮

## 2026-10-26 更新（#32 合并之后）

- **Gemini 的 `bars` 已经由 #32（@SkywingJam）交出来了**：两端解析每个窗口给一项 `{ label: "池名 窗口名", left, reset?, group: 池名 }`，`text` 每个池只显示一行（挑窗口规则见 `quota-aggregate.js` 的 `pickBar`）。原计划「Gemini 两端交 bars」这一步不用做了。
- **单家显示的额度条也按池挑**：`bars` 有好几个池（`group` 不同）时，每个池只画一条，用同一个 `pickBar` 挑，标签是「池名 窗口名」（比如「Gemini 5小时」「Argon 本周」「Claude/GPT 本周」），和文字样式一样多行；只有一个池时每个窗口一条（Claude、GPT）。
- **合并显示沿用 #32 的排法**（Gemini + Arg 一行、Agy C/G 一行，放不下时并回一行），额度条样式只把每一格从文字换成「短条 + 百分比」。格子里**不写窗口名（5h、周）和重置时间**；但**池名（Arg、C/G）保留**，不然 Gemini 那一行的几根短条分不清（我的决定）。
- **颜色变化（loki 10-26 要求）**：条和百分比按剩余分三档——多于 30% 蓝色，10%–30% 橙色，10% 及以下红色（档位我的决定）。单家和合并显示一样。
