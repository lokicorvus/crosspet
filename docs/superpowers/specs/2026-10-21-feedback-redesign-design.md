# 反馈功能重构：按问题类型附信息 · 设计

日期：2026-10-21　状态：方向 loki 已确认，待审阅本文；放 1.3.8 做（loki 定）

## 为什么做

「反馈问题」现在是：用户点一个或几个类型、写一句话，然后**不管选了什么**都附上同一大包东西——十个 AI 的接入诊断（大多是「从没收到」）、运行状态、最近日志。读反馈的是 Claude 和 GPT（loki 只负责转），结果是信息多却不对路：

- 无关的占了大半（只接了 Codex 的人，反馈里也列着另外九个 AI）
- 该有的没有：Mac 的「最近日志」其实是**更新日志**（`~/Library/Logs/CrossPet-update.log`），运行时的事一条都没有；「她不动」时看不出事件到了钩子以后被丢在哪；「只剩两个角色」时看不到角色文件夹的情况；「她不见了」时不知道反馈是不是在出问题那一刻发的
- 2026-10-21 的几份反馈都因此要回头再问用户，或者靠在 loki 电脑上临时插桩

loki 的要求：**按哪个角色、哪里出了问题，附对应的信息**；用户可以多点几下，把问题类型分清楚；反馈 / 诊断能力要整体设计一次，不再按单个 bug 零碎往上加（见 memory「CrossPet 诊断不零碎加」）。

## 目标

- 反馈窗口改成 4 步、**一页排开**（loki 从两种方案里选了 A）：选完第 1 步，下面的问题跟着出现
- 每份反馈只附**这一类**排查用得上的信息；省下来的篇幅用来附以前没有的关键信息
- 为此先打五块「地基」：Mac 运行日志、钩子事件记录、桌宠收到事件后的处理记录、换角色记录、网页自报显示状态
- Mac 和 Windows 一起做

不做：
- 不换发送渠道（仍是飞书群机器人，单条 20 KB）
- 不附截图、不附对话内容
- 不做自动诊断 / 自动回复用户
- 不加新的设置项

反目标（做出来但算失败的样子）：
- 反馈里出现任何对话内容（用户发的话、AI 的回答、工具参数和结果）、API Key、令牌、账号、邮箱；路径里的用户名没隐去
- 用户觉得步骤太多不想发：除了写一句话，最多 3 次选择再加「发送」（loki：可以让用户多点几下，分清问题类型）
- 附上的东西比现在还长、还乱；或者某一类该有的信息因为截断丢了

## 一、反馈窗口（feedback.html）

一页，从上到下：

1. **遇到了什么？**（单选，必选；原来是多选，改单选是因为附什么要按它定）

   | 类型 id | 用户看到的 | 小字 |
   |---|---|---|
   | `gone` | 她不见了 / 打不开 | 崩溃、闪退、找不到她 |
   | `action` | AI 干活时她没反应 | 或者动作、表情不对 |
   | `character` | 角色换得不对 | 换错人、少了角色 |
   | `quota` | 额度 / 余额不对 | |
   | `display` | 画面不对 | 错位、模糊、大小不对 |
   | `update` | 更新失败 | |
   | `perf` | 卡顿 / 耗电 | |
   | `idea` | 建议 / 想要 / 夸夸 | 立绘建议、想要新角色或新 AI、夸夸 |
   | `other` | 其他 | |

2. **补一个**（按类型出现，单选，必选；其他类型没有这一步）
   - `action`：是哪个 AI 在干活？只列**已接入**的宿主，外加「不确定」。ChatGPT 桌面版和 Codex 共用一套钩子，但用户分得清，单独列（我的决定，选它时附的是同一个宿主的记录，另外注明用户说的是桌面版）
   - `character`：是哪个角色？列所有可选角色，外加「角色列表里少了」
   - `quota`：哪一家的额度？只列打开了的额度来源
3. **问题现在还在吗？**（单选，必选；`idea` 没有这一步）：还在 / 刚过去（几分钟内）/ 更早
4. **一句话说说**：按类型给示例提示（沿用现在 HINTS 的写法）；`idea` 可以不填，其他至少 2 个字

下面照旧是「附上排查用的信息（不含对话和密钥）」勾选框（默认勾上）和「看看会发什么」预览，预览显示的就是这一类真正会发的内容。

**不勾**时只发：版本、平台、用户选的三项、用户写的话（我的决定：隐私界线，系统版本、机器编号、运行时长、衣服都算排查信息，不勾就不发）。

## 二、每份反馈都带的开头

版本（含测试版后缀）、平台、系统版本和芯片架构、机器编号前 8 位、当前角色和衣服、已经运行多久、用户选的三项（类型 / 补选 / 还在吗）、用户写的话。开头和用户的话**永远不截断**。

## 三、每类附什么

「相关日志」都是指运行日志里和这一类有关的最近若干行（按关键词或日志分类筛，筛法留给实现），不再整段贴尾巴。

### `gone` 她不见了 / 打不开
- 窗口：位置大小、在不在任何屏幕里、是否显示、透明度、置顶与否、显示层级
- 每块屏幕：分辨率、系统缩放、相对位置、桌宠在哪块
- 前台窗口：程序名，以及**是不是桌面 / 任务栏**（Windows 看窗口类名，Mac 看是不是 Finder 的桌面）
- 是否被别的窗口挡住（Mac 用 occlusionState，Windows 用现有的 Covered）
- 所有「藏起来」的原因各自的状态：全屏收着、快捷键藏着、从菜单退出（用户退出标记）、锁屏
- 网页自报（见第四节 4）
- 渲染重启记录（Windows `render-restart.txt` 的次数和时间）
- 安装是否完整（复用 InstallCheck / Mac 包内文件检查）
- Mac：`~/Library/Logs/DiagnosticReports` 里 CrossPet 的崩溃报告数量和最近一份的时间（只要这两样）
- 相关日志：窗口、全屏、层级、渲染、启动、崩溃

### `action` AI 干活时她没反应（补选了某个 AI）
- **只附这一个宿主**：它的接入诊断（`integrate.py diagnose` 里这一段）、最近收到消息的时间
- 它的**事件记录**最近 40 条（见第四节 2），以及**桌宠这一侧对同一批事件的处理记录**最近 40 条（见第四节 3）——两份对起来看，就知道事件是在钩子丢的、在桌宠丢的，还是演了却没被看到；这是这一类的核心
- 宿主的插件 / 钩子版本：没有事件记录时，写明是「插件版本早于 1.3.8、还没有记录」还是「从没收到」，免得误读
- 它的状态文件（pose、event、tool、时间）、多会话文件、轮次记录（`<宿主>-turns.json`）、按模型换角色的记录（`<宿主>-host.json`）
- 跟随前台 / 跟随事件 / AI 干活自动出现三个开关，当前角色
- 宿主程序版本（如 codex-cli 版本、Harness 插件版本和自检）
- 钩子用的 Python 路径和版本
- 「不确定」：所有已接入宿主各附最近收到消息时间和最近 10 条事件记录
- 相关日志：状态、接入、自动出现

### `character` 角色换得不对（补选了某个角色，或「角色列表里少了」）
- **角色文件夹对照表**：安装目录和数据目录里每个角色 / 皮肤文件夹一行——`character.json` 能不能读、有没有 idle 立绘、立绘几张、最终加载了没有、没加载的原因（读不出 / 缺 idle / 复制失败）
- **换角色记录**最近 40 条（见第四节 3）
- 前台程序和它对应的角色、跟随前台 / 跟随事件开关、各宿主的按模型换角色记录、穿着的衣服、峰谷换装设置
- 补选了某个角色时，额外附她的文件夹那一行展开（立绘清单的姿态名）
- 相关日志：同步角色、换角色

### `quota` 额度 / 余额不对（补选了哪一家）
- 这一家：最近一次读到的值、什么时候、花了多久、最近一次失败的原因
- 去哪查的：GPT——codex 程序路径和版本；Gemini——有没有找到 Antigravity 的服务进程、监听端口几个、两个接口各自的 HTTP 状态和解析结果（只要状态码和字段是否齐，不要正文；做法参考 `crosspet-test/排查报告/antigravity-quota-diagnose.py`）；DeepSeek——插件自检、余额来源（Key / 账号）、币种
- 相关开关（额度开关、合并显示、重置提醒、低余额门槛）
- 相关日志：额度

### `display` 画面不对
- 每块屏幕的系统缩放、网页缩放、画布量出来的实际大小 / 应有大小、人物大小、文字大小
- 网页自报（当前立绘、图片实际尺寸）
- 相关日志：缩放、画布、网页大小

### `update` 更新失败
- 更新日志（Mac `CrossPet-update.log`、Windows `update.log`）最近 100 行——**只有这一类附它**
- 安装目录里每个必需文件夹在不在、旁边有没有 `.new` / `.old` 残留、下载缓存里有哪些版本

### `perf` 卡顿 / 耗电
- CrossPet 进程和它的网页进程（WebView2 / WKWebView 的 WebContent）当前 CPU、内存（取一次即可）
- 省电开关、开着哪些定时查询及间隔、显示器刷新率
- 相关日志：渲染、定时任务出错

### `idea`、`other`
- `idea`：只有开头，不附别的
- `other`：说不清是哪类时用，每类都带一点——窗口、显示器、前台、藏起来的原因、网页自报、设置、各已接入宿主最近收到消息、每家最近 10 条事件记录、桌宠处理记录、最近换角色、安装、最近 60 行日志（loki：原来太少，啥都看不到；体积由缩减规则兜着）

## 四、地基：先要有的五样记录

这五样现在都没有。它们按上面的分类统一设计，各有固定用途，不是零碎补丁。都只存在用户自己电脑上，只在用户发反馈时附上；都不记任何内容。

### 1. Mac 运行日志
- 和 Windows `windows.log` 同样的写法：`~/Library/Logs/CrossPet.log`，一行一条带时间，超过 1 MB 时保留后一半（Windows 现在怎么限的就怎么限，保持一致）
- 把 Mac 现有的 NSLog 和该记的事件（启动、全屏收放、层级变化、换角色、接入、额度失败、立绘加载失败……对齐 Windows 现在记的那些）都写进去
- Windows 不变

### 2. 钩子事件记录（每个宿主一份）
- 文件：**数据目录**下 `events/<接入名>.jsonl`（我的决定：Mac 的状态目录是 `/tmp/crosspet`，重启就清空，「问题更早发生」或重启后才反馈时证据就没了；数据目录是持久的，`crosspet-hook.py` 和各插件本来就知道它在哪）。只留最近 200 行，写入时超了就截掉旧的
- 接入名用 `integrate.py` 和反馈里「最近收到消息」已经在用的那套：`codex`、`claude-hooks`、`claude-mod`、`deepseek`、`antigravity`、`gemini`、`qwen`、`workbuddy`、`zcode`、`hermes`（我的决定：现在的 `seen-<键>` 有的按角色、有的按宿主，不能直接拿来当文件名；反馈第二步「哪个 AI」的选项也一一对应这些接入名，「ChatGPT 桌面版」对应 `codex`）
- 每行：时间、事件名、工具名（只有名字）、会话的短标识（会话 id 的哈希前 6 位，用来分清多个会话，不可逆）、有没有轮次号、**处理结果**：
  - `shown <角色> <姿态>`：演了
  - `dropped <规则名>`：被哪条规则丢了，规则名固定，比如 `codex-memory`（工作目录在 Codex 配置目录里）、`codex-suggestion`（没有对话记录文件）、`turn-finished`（轮次已结束）、`unknown-event`、`bad-json`
  - `error <异常类型>`：钩子自己出错了（只记异常类型，不记消息里可能带的内容）
- **绝不记**：prompt、tool_input、tool_response、last_assistant_message、对话记录路径、工作目录（工作目录可能含项目名；只在丢弃原因和它有关时记「在 / 不在 Codex 配置目录里」）
- 所有写事件的地方都要写：`crosspet-hook.py`（Claude Code、Codex、Gemini CLI、Antigravity、Qwen Code、WorkBuddy、ZCode）、DeepSeek Harness 插件、Hermes 插件、Claude Code 增强版 mod。格式统一，写一个共用的说明（放进 `docs/架构.md`）
- 写记录失败不能影响钩子本身
- 已经接入的用户怎么拿到新钩子：`crosspet-hook.py` 每次启动随包同步；Claude Code mod、DeepSeek Harness 插件已有启动同步或「插件更新提醒」（DSH 插件版本号要升）；Hermes 插件跟着现有的刷新接入流程走。不另做强制刷新（我的决定），反馈里按上一节写明「插件太旧、还没有记录」

### 3. 桌宠收到事件后的处理记录
钩子写出状态文件只说明「钩子这边演了」，桌宠那边还可能丢：Mac 只认 10 分钟内的状态、开发者控制台预演时暂停真实事件、前台 AI 优先挡掉别的角色的事件、等网页答复期间前台或开关变了丢掉这次答复、网页收到的不是当前角色就不演。
- 由外壳在读到状态变化的那一处记（判断仍在原来的地方，只是把结论写下来），数据目录下 `events/pet.jsonl`，只留最近 200 行
- 每行：时间、哪个角色的状态、事件名 / 姿态、**结论**：`played`（交给网页演了）或 `skipped <原因>`，原因名固定，比如 `stale`（超过 10 分钟）、`paused`（预演中）、`front-ai`（前台 AI 优先）、`answer-stale`（等答复期间情况变了）、`not-current`（不是当前角色，只记下状态）
- 和钩子的事件记录一样只记名字，不记内容
- 我的决定：分成钩子一份、桌宠一份两种文件，各由自己写，不让外壳往钩子的文件里追加（钩子是多个进程同时写，少一个写入方少一种并发问题）

### 4. 换角色记录
- 由外壳在真正换角色的那一处记（Mac `switchTo`、Windows `SwitchTo`），数据目录下 `switches.jsonl`，只留最近 200 行
- 每行：时间、从谁、换到谁（含衣服）、原因：`front`（跟随前台，带程序名）、`event`（跟随事件，带宿主）、`host`（按模型换）、`manual`（菜单 / 设置）、`startup`、`peak`（峰谷换装）、`skin`（换衣服）、`fallback`（当前角色不存在了换成别的）
- 被拦下没换的不在这里记，在第 3 条桌宠的处理记录里（`front-ai`）

### 5. 网页自报显示状态
- `index.html` 新函数（名字留给实现），外壳发反馈时调用一次，返回：当前角色 / 姿态、正在显示的那张图（文件名，不含路径）、它加载完没有和实际尺寸、两张交替图的状态、是否正在换角色的半路、是否缩在边上、是否在演彩蛋、页面是否被藏（setPageHidden）、最近 5 次图片加载失败的文件名和时间
- 网页没响应（比如画面冻住）时写「网页没有回应」，这本身就是重要信息

## 五、体积

按真实数据估算（单条上限 20 KB，留 1 KB 余量）：开头约 0.5 KB；`gone` 约 7 KB，`action` 约 7 KB，`character` 约 4.5 KB，`quota` 约 3.5 KB，`update` 约 8 KB。都在上限一半以内。

超了照现在的办法按比例缩，顺序：先缩相关日志，再缩事件 / 换角色记录的条数（保留最新的），开头和用户的话不缩。

## 六、程序分工

- **网页层**（判断只写一份，见 `docs/架构.md`）：`feedback.html` 的四步界面；「这一类要附哪几段、按什么顺序、超了怎么缩」的规则做成纯函数模块（名字留给实现），node 测试
- **外壳**：按网页要的段落收集原始数据交给网页（系统接口：窗口、屏幕、进程、文件、日志）；网页负责拼成飞书卡片。现在 Mac / Windows 各自拼 runtime 字符串的做法改掉
- 打码：路径里的用户名隐去（沿用现有 redact），两端一致
- 钩子事件记录：`crosspet-hook.py` 和各插件；Python / JS / TS 三份实现，格式一致
- 桌宠处理记录、换角色记录：两个外壳各写一份，格式一致

## 七、测试

- 网页规则模块：每一类附哪些段、缩减顺序、`idea` 不附、开头不被截断（node）
- 钩子事件记录：每条丢弃规则写出正确的规则名；记录里不出现 prompt / tool_input 等字段（构造带敏感内容的事件，断言记录里搜不到）；超过 200 行截断（python unittest，沿用 `tests/codex_turn_test.py` 的跑法）；插件侧同样的断言（node）
- 换角色记录：Windows LogicTests 能测的部分（行格式、截断）
- 两端编译；Mac 实测每一类发一份到飞书（或本地预览）看内容；Windows 由 Codex 跑一轮
