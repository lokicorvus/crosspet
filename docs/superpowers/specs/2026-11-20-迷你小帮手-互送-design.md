# 迷你小帮手：好友互送、围在身边 · 设计

状态：待 loki 审。接替 2026-11-19-迷你小帮手-design.md（那份是试画阶段的草稿，素材部分仍然有效）。

## 为什么做

桌宠之间已经有好感度（friendship.js：一起在场、同时干活、前后脚干完、轮流摸头攒分，0–10 颗心，关系分「认识了 / 好朋友 / 挚友」）。好感度现在只体现在设置页的心和小本子上，看不见摸不着。迷你小帮手把它变成桌面上看得见的东西：好朋友之间互送自己的小帮手，收到的小帮手一直陪在她脚边。只开一只桌宠的人也能看到她自己的小帮手。

## 现状（已经做好的）

- 素材：14 套小帮手（Claude、DeepSeek、Gemini、GLM、GPT、Grok、Kimi、Qwen 原版 + 圣女、DeepSeek 卫衣 / 毛衣 / 睡衣 / 冬装、魔术师），每套 4 张格子图，GPT 连体衣还没画。
  - 出题：`tools/mini_art.py`（art.py 的外挂：画风参考、皮肤拿原版改衣服）；批次 `art/任务/2026-11-19-迷你小帮手-试画`、`…-全员`。
  - 切图：`tools/mini_cut.py` 切成 17 帧，拼成横条 `characters/<id>/mini.webp`（每格 136×148，顺序见 `tools/mini_sheet.py` 的 FRAMES）。外壳把它当「姿态 mini」扫进清单，皮肤自带自己那套。
- 桌宠：`app/web/mini-helper.js` 已经能画**一个**小帮手（她自己的），按她的姿态换动作（moodOf），绕圈跑、换帧全是 CSS 动画；`index.html` 的 `syncMini()` 接在 setPose 后面。贴边藏起来。
- 临时预览：`build/mini-preview/`（单个，动作）、`build/mini-crowd/`（几个一起）。不进 git，做完删。

## 目标

1. 设置里一个开关「显示小帮手」，默认开。关了谁都不显示。
2. 只开一只桌宠：身边是她自己的小帮手。
3. 多桌宠：两个 AI 升到「好朋友」（4 颗心）时互送小帮手，演一次送礼。送了就永久归她，以后只开她一只也在。
4. 身边最多 6 个：她自己的 + 最多 5 个好友送的。
5. 大家错开做事，不整齐划一；GPT 飞、DeepSeek 游、Gemini 和 GLM 扑跳，其他人跑。

## 不做（这一版）

- 不在设置里勾选带谁（好友超过 5 个时每天轮换，见下）。要 7 只桌宠一起开上几周才会超过，先不做；以后要再加。
- 点小帮手没反应（桌宠窗口只认她身上的点击，不改 hitRects）。
- 不给 Claude、Kimi、Qwen、Grok 画专属移动方式（她们照旧跑）。
- 彩蛋角色没有小帮手。用户自己做的角色：有 mini.webp 就有，没有就没有，不提供工具。

## 反目标（做出来也算失败的情况）

- 小帮手挡住她：脸、手里的东西、气泡、额度栏。只能在她脚边和身后。
- 6 个一起时糊成一团，认不出谁是谁。
- 一直动个不停让人分心：闲着时大部分时间是站着的，偶尔才有人动。
- 拖慢桌宠：绕圈、换帧只用 CSS 动画，不用 JS 每帧算；省电模式下照样能用。
- 换角色、换衣服、贴边、让开（变透明）时小帮手残留、闪一下或位置错乱。

## 做法

考虑过三种：

- A. 全放网页共用的 localStorage，设置页直接读写。外壳几乎不改，但开关和其他设置不是一条路，数据丢了找不回。
- B. 全交外壳（像「不睡觉」）：开关、送礼记录都存外壳设置，推给每只桌宠。最规整，Swift 和 C# 各写一遍存储和推送，代码最多。
- **C. 混合（选了这个）**：送礼记录挂在好感度记录上，开关走外壳设置。送礼和好感度本来是一回事，放一起不会对不上；好感度记录已经由外壳另存 `friendship.json` 并负责找回，送礼记录跟着就有备份。开关和「不睡觉」一样走外壳，两边各加一个开关。

### 送礼记录

- 「谁收到了谁的」直接从好感度算：这一对的 `Friendship.level(points) >= 2` 就算互送过了。分数只涨不跌，所以送了就不会没。不另存一份名单。
- 送礼演没演过另记：好感度记录每一对已经有 `shown`（演过的最高关系，pair-chat 的「关系升级」用）。加一个 `giftShown: true`，演完送礼写上。
  - 新升到好朋友：「关系升级」那段对话演完（tryPairChat 里 `up.level === 2`）接着演送礼，写 giftShown。
  - 老用户：level ≥ 2 但没有 giftShown 的一对，下次两只同时在桌面上、都闲着时补演一次（和关系升级同一套条件：presentCharacters、不忙、隔 30 秒）。补演之前小帮手**已经**在身边了（因为送礼是按 level 算的），补演只是个仪式。
  - `Friendship.merge` 是整条记录取分数高的那份：备份那份分数高但没有 giftShown 时会把网页的冲掉，送礼就会再演一遍。改成取分数高的那份、giftShown 两边有一个是 true 就留 true（我的决定）。
- 好感度开关（多桌宠没开时 friendshipOn 是 false）不影响已经收到的：只要好感度记录里 level ≥ 2 就显示。

### 显示哪几个

`MiniHelper.crew(receiver, { store, manifest, today })` → 有序列表，纯函数、能测：

1. 第一个是她自己（manifest 里她有 poses.mini 才有）。
2. 好友：好感度记录里和她这一对 level ≥ 2、对方在 manifest 里有 poses.mini 的，按分数从高到低。
3. 超过 5 个：按 `今天日期 + 她的 id` 做种子，从里面挑 5 个（同一天、同一只桌宠结果不变；换一天换一批）。
4. 每一项：`{ id, sheet: manifest.characters[id].poses.mini[0], move: 'run' | 'fly' | 'swim' | 'pounce' }`。move 按原版 id 定：gpt → fly，deepseek → swim，gemini、glm → pounce，其他 run；皮肤的 id 就是原版 id（清单里皮肤是换掉原版的图，id 不变），所以自然跟着原版。

主桌宠和额外那只各自算自己的（额外那只也能读共用的 localStorage 里的好感度）。好感度变了（升级、补演完）、换角色、换衣服（外壳重新 init）时重算。

### 摆放和动作

小帮手层从「一个」改成「一组」：mini-helper.js 的 attach 管一组 `#mini` 元素，每个和现在一样（外层定位、z 层、翻转、精灵图）。

- 尺寸：站着 43 像素（画布 250×241 里，桌宠人物约 181 高），和现在一样。
- 站位（待机时，画布坐标，离中线左右、前后）：按顺序填，第一个是她自己。参考预览定的顺序：右、左、更外的右、更外的左、脚前偏右、脚前偏左。**全部要在画布里**（画布半宽 125，小帮手半宽约 21，所以离中线最多约 100）；靠前的盖住靠后的。具体数值在桌宠里调到不挡她的脚和裙摆、不出画布为止。
- 她闲着：大部分时间站在自己的位置轻轻晃。每个有自己的计时（错开，9–20 秒随机），轮到了做一件小事：跑一圈回原位、挥挥手、坐下看会儿书、（她自己的那个）偶尔记笔记。同一时刻最多 1 个在绕圈。
- 她干活：最多 3 个绕圈（在圈上均匀错开），其余的在原位做「忙的样子」：看书、记笔记、思考。每 2 分钟左右重新分一次谁跑谁坐。
- 她思考 / 读 / 等你 / 睡觉 / 开心 / 出错 / 打招呼：和现在单个时一样的对应（moodOf），每个错开一点开始，不要齐刷刷一起换。
- 贴边：全部藏起来。让开（整页变透明）：跟着一起透明（已经是）。换角色：跟着舞台一起淡出淡入，换完重算 crew。

### 专属移动方式（要画图）

- 新姿态 `mini_move`：一张横图一排 3 帧，朝右：
  - fly（GPT）：振翅飞，翅膀上 / 平 / 下三帧，脚离地。
  - swim（DeepSeek 和 4 套皮肤）：在半空像游泳，身体横一点、鲸鱼尾巴摆。
  - pounce（Gemini、魔术师、GLM）：猫 / 狐狸那样扑跳：蓄力、腾空、落地。
- 一共 9 张：GPT 1，DeepSeek 原版 + 4 皮肤 5，Gemini + 魔术师 2，GLM 1。规则 `art/规则/迷你-移动.txt`，用 `tools/mini_art.py` 出题（皮肤拿原版改衣服）。
- 拼图：FRAMES 末尾加 `move-a`、`move-b`、`move-c`（格子 17 → 20）。没有 mini_move 的角色（照旧跑的）这三格放跑步帧，网页不用判断有没有。mini_sheet.py、mini_cut.py、mini-helper.js 的 FRAMES 一起改，已有的 mini.webp 全部重拼。
- 绕圈路径按 move 不同（仍然全是 CSS 动画）：
  - run：现在这样。
  - fly：同一个圈，但离地高一截（画布里约 25 像素），一路上下起伏；在她身后时照样被挡。
  - swim：同一个圈，离地一点，上下起伏更大更慢，像游泳。
  - pounce：同一个圈，一跳一跳（几段弧线），落地那下停一拍。
- 抱书跑（她干活时）怎么办：fly / swim / pounce 的角色干活时也用自己的移动帧，不抱书（抱书跑的帧仍然给跑的人用）。

### 送礼那一幕

两只同时在桌面上、升到好朋友（或老用户补演）：

1. 「关系升级」对话照常（pair-chat）。
2. 对话完：A 的桌宠脚边出现 B 的小帮手（从上面落下来、捧礼物鞠躬，mini-helper.js 里已经有 `gift()`），B 那边同时出现 A 的。演完各自归队。主桌宠演自己那边；额外那只的那边由外壳转（和 pair-chat 说话一样走 companionCall）。
3. 小本子第二页：在「关系升级」那条留言后面加一句收到小帮手。现在 notebook-diary.js 记 levelup 事件、notebook-events.js 出留言；最省事是升到 2 的那条模板里加一句「送你一只我的小帮手」，每个角色的 up2 改写一下。（builder 定具体放哪）
4. 写 giftShown。

### 设置

- 「显示小帮手」开关：放在设置的角色页（「她们的友谊」上面或旁边的一项），说明写「她身边陪着小帮手；和别的 AI 成为好朋友后会互送，收到的也会一起陪着（最多 6 个）」。
- 外壳：Mac 和 Windows 都加 `showMinis`（默认 true），设置页 `post({ cmd: 'set', key: 'showMinis' })` → 存外壳设置 → `js("setShowMinis(on)")`，额外那只启动时和「不睡觉」一样一起推（App+Companions.swift、Pet.Companions.cs 那一串）。
- 网页 `setShowMinis(on)`：关了整组收起。

## 约束

- 两个外壳（Swift、C#）都要改设置；不改外壳的扫描（mini.webp 已经被当成姿态扫进来）。
- Windows 立绘只能从 `characters/<id>/<文件>` 读，不能有子目录（SpritePath）。
- 桌宠画布 250×241（#stage），窗口按「画布 × 人物大小」，小帮手不能出画布。
- 开发者控制台已经把 mini 从姿态列表里去掉了。
- `tools/art.py` 有 loki 没提交的改动，不要改；迷你相关的出题全走 `tools/mini_art.py`。
