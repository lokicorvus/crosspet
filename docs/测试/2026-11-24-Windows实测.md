# Windows 实测：1.4.0 之后这一轮（2026-11-24）

给在 Windows 上做测试的 AI（Codex）。按顺序做，每项都写清楚结果，最后按「怎么回报」交一份报告。

## 先读：规矩

- **只测、不改代码。** 发现问题就记下现象、日志和复现步骤，不要动仓库里的文件，不要提交、推送、发版。
- **先备份，测完还原。** 这台电脑上可能装着用户自己在用的 CrossPet。动手前按「0. 准备」备份数据目录和开机自启那一项，全部测完后按「9. 收尾」还原。
- **不要卸载、也不要新接入任何 AI。** 只在第 5 项里给 DeepSeek Harness 点一下插件「更新」。
- 不要读、不要贴出任何令牌、API Key、密码（包括 `%LOCALAPPDATA%\CrossPet` 里的、Antigravity 的 `daemon\hub_*.json` 里的）。报告里引用文件时只贴和本项有关的字段。
- 需要看画面的项（第 6、7、8 项）：能截图就截图附上；没法看画面的，写「需要用户看」，不要猜。
- 每项的结果只写三种：**通过**、**不通过**、**没法测**（写原因，比如电脑上没装 DeepSeek Harness）。

## 要用到的东西

| 东西 | 位置 |
|---|---|
| 新包（这次要测的） | 用户给你的 `CrossPet-Windows.zip`（在 Mac 上 `build/CrossPet-Windows.zip` 打的，版本号仍是 1.4.0） |
| 旧版 1.4.0 正式包 | https://github.com/lokicorvus/crosspet/releases/download/v1.4.0/CrossPet-Windows.zip |
| 数据目录 | `%LOCALAPPDATA%\CrossPet`（`settings.json`、`windows.log`、`update.log`、`state\`） |
| 默认安装位置 | `%LOCALAPPDATA%\Programs\CrossPet` |
| 开机自启 | 注册表 `HKCU:\Software\Microsoft\Windows\CurrentVersion\Run` 里名为 `CrossPet` 的值 |

两个包的版本号都是 1.4.0，**分辨新旧靠这个**：新包的 `web\settings.html` 里有 `minisFrom`，旧包没有。

```powershell
Select-String -Path "<某个 CrossPet 文件夹>\web\settings.html" -Pattern minisFrom -Quiet   # True = 新版
```

## 0. 准备

```powershell
$T = "$env:USERPROFILE\crosspet-test"; New-Item -ItemType Directory -Force $T | Out-Null
Get-Process CrossPet -ErrorAction SilentlyContinue | Stop-Process          # 先关掉在跑的 CrossPet
Copy-Item "$env:LOCALAPPDATA\CrossPet" "$T\data-backup" -Recurse            # 备份数据目录（没有就跳过）
Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run' -Name CrossPet -ErrorAction SilentlyContinue |
  Select-Object -ExpandProperty CrossPet | Set-Content "$T\run-backup.txt"   # 记下开机自启原来指着哪（没有就是空文件）
Test-Path "$env:LOCALAPPDATA\Programs\CrossPet"                             # 记下：Programs 里本来有没有装
```

把新包解压到 `$T\new`（解压后是 `$T\new\CrossPet\...`），旧包解压到 `$T\old`。

## 1. 安装脚本能被 Windows PowerShell 5.1 解析

```powershell
powershell -NoProfile -Command "[void][scriptblock]::Create((Get-Content -Raw -Encoding UTF8 '$T\new\CrossPet\install.ps1')); 'OK'"
```

**通过**：输出 `OK`。报语法错误就是不通过，把错误原文贴上。

## 2. 一键更新装回正在用的文件夹（这轮最重要）

背景：用户反馈「更新完再打开又是旧版、又提示更新」。以前一键更新总是装到 `Programs\CrossPet`，而用户在别处（文档、D 盘）放着另一份、从那里打开或开机自启。现在桌宠调用 `install.ps1 -Update -Target <它自己所在的文件夹>`，安装脚本原地换掉那一份，并把开机自启改指过去。

### 2a. 原地更新

```powershell
$D = "$env:USERPROFILE\Documents\CrossPet"
Copy-Item "$T\old\CrossPet" $D -Recurse                       # 模拟用户把旧版放在「文档」里
Set-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run' -Name CrossPet -Value "`"$D\CrossPet.exe`""
Start-Process "$D\CrossPet.exe"; Start-Sleep 8                 # 旧版在跑（真实更新时也是这样）
Remove-Item "$env:LOCALAPPDATA\CrossPet\update.log" -ErrorAction SilentlyContinue
Get-Process CrossPet | Stop-Process; Start-Sleep 2             # 真实更新时旧版自己会退出
powershell -NoProfile -ExecutionPolicy Bypass -File "$T\new\CrossPet\install.ps1" -Update -Target $D
Start-Sleep 5
```

检查并贴结果：

1. `Select-String -Path "$D\web\settings.html" -Pattern minisFrom -Quiet` → 应为 `True`（文档里那份换成了新版）。
2. `Get-Content "$env:LOCALAPPDATA\CrossPet\update.log"` → 应有一行 `已安装到 C:\Users\…\Documents\CrossPet`，没有「安装失败」。
3. `Get-Process CrossPet | Select-Object Path` → 在跑的是 `$D\CrossPet.exe`。
4. `Get-ChildItem (Split-Path $D) -Filter 'CrossPet.*'` → 不应留下 `CrossPet.new`、`CrossPet.old-*`。
5. 开机自启那一项还是指着 `$D\CrossPet.exe`。
6. 开始菜单快捷方式 `"$([Environment]::GetFolderPath('Programs'))\CrossPet.lnk"` 的目标是 `$D\CrossPet.exe`：
   `(New-Object -ComObject WScript.Shell).CreateShortcut("<上面的路径>").TargetPath`

### 2b. 文件夹里有别的东西：不原地换，装到 Programs

```powershell
Get-Process CrossPet -ErrorAction SilentlyContinue | Stop-Process; Start-Sleep 2
Set-Content "$D\我的笔记.txt" "test"
Remove-Item "$env:LOCALAPPDATA\CrossPet\update.log" -ErrorAction SilentlyContinue
powershell -NoProfile -ExecutionPolicy Bypass -File "$T\new\CrossPet\install.ps1" -Update -Target $D
Start-Sleep 5
```

检查：

1. `update.log` 里有一句「…Documents\CrossPet 里还有别的东西（我的笔记.txt），不在那里原地更新，装到 …Programs\CrossPet」，然后是「已安装到 …Programs\CrossPet」。
2. `$D\我的笔记.txt` 还在，`$D` 里的文件没被删。
3. 开机自启原来指着 `$D\CrossPet.exe`，现在应改成 `…\Programs\CrossPet\CrossPet.exe`；`update.log` 里有一句「开机自启原来指着 …，改成 …」。

### 2c. 不带 -Target（旧版的调用方式）、也不是从 CrossPet.exe 调用的：照旧装到 Programs

```powershell
Get-Process CrossPet -ErrorAction SilentlyContinue | Stop-Process; Start-Sleep 2
Remove-Item "$env:LOCALAPPDATA\CrossPet\update.log" -ErrorAction SilentlyContinue
powershell -NoProfile -ExecutionPolicy Bypass -File "$T\new\CrossPet\install.ps1" -Update
Start-Sleep 5
```

检查：`update.log` 是「已安装到 …Programs\CrossPet」，没有报错。

> 没法在这里测的一条：1.4.0 旧版从右键菜单点「更新」（不传 -Target，脚本看父进程是哪个 CrossPet.exe 来装回原处）。这要 GitHub 上真的有更新的版本才会出现，等用户发测试版后再测。报告里列为「没法测」即可。

测完 2 之后，把 `$D` 整个删掉（`Remove-Item $D -Recurse -Force`），它是测试用的。

## 3. 全新安装（双击 install.cmd 的路径）

```powershell
Get-Process CrossPet -ErrorAction SilentlyContinue | Stop-Process; Start-Sleep 2
& "$T\new\CrossPet\install.cmd"
```

install.cmd 只在出错时停在「按任意键」，停了就是不通过，把窗口里的文字贴上。**通过**：装到 `Programs\CrossPet`，桌宠出现，`windows.log` 最后有「启动 1.4.0」，没有「崩溃」「启动失败」。

## 4. 设置项「显示谁的」小帮手

在设置窗口（右键桌宠 →「设置…」→「角色」页）里，「显示小帮手」下面应有一行「显示谁的」：「只有她自己的」/「也显示朋友送的」（默认后者）。

- 能操作界面：点「只有她自己的」→ `settings.json` 里出现 `"minisFrom": "own"`，桌宠旁边只剩她自己的小帮手；点回「也显示朋友送的」→ 变成 `"all"`，朋友送的回来。关掉再打开桌宠，选择还在。关掉「显示小帮手」时这一行应该藏起来。
- 不能操作界面：只做文件检查——关掉桌宠，在 `settings.json` 里加 `"minisFrom": "own"`，再打开，`windows.log` 里没有报错即可；画面写「需要用户看」。

## 5. DeepSeek Harness 中途换模型（需要装了 DeepSeek Harness，并且配了 DeepSeek 和另一家模型，比如 GPT）

背景：多桌宠时，在 Harness 里同一个对话中途把模型从 DeepSeek 换成别家，DeepSeek 那只一直停在「听」或「思考」。插件 1.3.12 修了这个问题。

1. 设置「接入 AI」里 DeepSeek Harness 应提示插件可更新，点「更新」，然后**完全退出再打开 Harness**。
2. `Get-Content "$env:LOCALAPPDATA\CrossPet\state\deepseek-plugin.json"` 里 `"plugin"` 应为 `1.3.12`。
3. 打开设置里的多桌宠。在 Harness 里用 DeepSeek 模型发一句、等它答完；在同一个对话里把模型换成 GPT 再发一句、等它答完。
4. 查 `state\deepseek-state.json`：`pose` 应为 `idle`、`event` 应为 `Stop`。`state\deepseek@deepseek-state.json` 也一样。桌面上 DeepSeek 那只应回到待机，不停在听 / 思考。
5. 没装 Harness 就写「没法测」。

## 6. Antigravity 的 Gemini 额度（需要装了 Antigravity 并登录）

背景：2026-11-24 起 Google 把 Argon 并进了 Gemini 额度，现在只有两组：「Gemini」和「Claude/GPT」，每组有 5 小时和本周两个窗口。Antigravity 2.34 起本机服务的令牌写在 `%USERPROFILE%\.gemini\antigravity\daemon\hub_<端口>.json`，Windows 上一直没实测过。

1. 开着 Antigravity，切到 Gemini 当前角色（让 Antigravity 在前台即可），等一两分钟。
2. 问到的额度只在桌宠内存里，不写文件（`state\gemini-quota.json` 是 Gemini CLI 接入写的，和这里无关），所以看画面：名牌下面应有额度，**不应出现 Argon**。右键桌宠 →「反馈」里诊断信息「找服务 …」那行应写着找到服务进程、令牌来自 daemon 文件或启动参数，贴上那行（不要贴令牌）。
3. 没数据时：同样贴「找服务 …」那行，再贴 `windows.log` 最后 30 行。
4. 设置「额度」页「显示 Gemini 额度」下面有「显示哪些」两档，默认「5小时和本周」：
   - 默认：名牌下面两行「5小时 剩余 …%」「本周 剩余 …%」，没有 Claude/GPT，只在剩得少的那行后面写重置时间（和 GPT 的额度一样）。
   - 点「5小时和 Claude/GPT」：立刻变成「Gemini 5小时 …」「Claude/GPT …」两行，不用等下次查询；`settings.json` 里 `"agyQuotaMode": "cg"`。点回去同理（`"week"`）。
   - 关掉「显示 Gemini 额度」时「显示哪些」这一行藏起来。
5. 关掉 Antigravity，等两三分钟：额度不消失，后面多了「HH:mm 的数据」（两种模式都是）；再打开 Antigravity，等一两分钟，「的数据」消失。
6. 「额度显示样式」选「额度条」时两种模式都看一下，条不应挤成很短一截（最短宽度从 30 改成了 56 像素）。截图附上。

3. 豆包被摸头（pat）是新图：两只手完整。
4. 换到 GPT「降智龙崽」皮肤，开着小帮手：小帮手是她自己那套（啃饼干、袖子盖住手），走路是跑着走，不飞。
