# SVG 动画时钟候选修复

基线：`d09e493fa9e5d718c2e585744432bcd7ddc3a816`（1.3.1）。分支：`fix/svg-animation-clock`。

## 问题和改动

1.3.0 的 `6e5777299c2e` 用 `pauseAnimations()` 和周期性 `setCurrentTime()` 代替 SVG 原生时钟：普通状态 30 FPS、省电 15 FPS、睡眠休息后 5 FPS。用户提供的录屏中，睡眠 z/Z 约每 200 毫秒出现单帧错位，时间与 5 FPS 推进吻合。

候选修复移除手动 SVG seek，让可见特效使用原生时钟；只在隐藏或闲置休息时 pause，在恢复时 unpause。新插入的 SVG 也同步当前暂停状态。保持普通模式 30 秒、省电模式 10 秒休息，以及隐藏时冻结 CSS 动画；睡眠特效保持播放。

取舍：不再强制限制活动期间的 30/15 FPS，睡眠也不再限制 5 FPS。活动期间 CPU 可能增加，目前没有新的 CPU/耗电测量，不能沿用原提交的活动耗电数据。设置与说明已同步这一行为。

## 已验证

设备环境：Apple Silicon、macOS 15.8（24H23）、Apple Swift 6.1.2、系统 WKWebView。测试窗口直接加载项目页面，没有启动完整 CrossPet，也没有读写其配置、状态或 AI 接入。

真实 WKWebView 回归测试包含 11 项检查：睡眠原生播放、没有可见期 SVG seek、隐藏时冻结、新增 SVG 随隐藏状态暂停和恢复、CSS 冻结、恢复不跨过隐藏时间、闲置休息、工作恢复、10/30 秒休息阈值、睡眠休息例外。

- 原版：5 项通过、6 项失败，测试返回非零。隐藏约 450 毫秒后恢复 120 毫秒，SVG 时间直接跨过约 452 毫秒。
- 修复版：11 项全部通过；相同隐藏/恢复流程只推进约 121 毫秒，隐藏期间时间增量为 0；可见期间 seek 次数为 0。
- 测试把真实 10/30 秒的休息定时缩短为 100 毫秒，同时检查请求的原始延时；未测量真实等待 30 秒的长期行为。
- 页面和测试脚本的 JavaScript 语法、shell 语法、`git diff --check` 通过。
- macOS arm64 和 x86_64 二进制均编译，合并成通用 App；Info.plist 校验及 `codesign --verify --deep --strict` 通过，使用 ad hoc 签名。
- 独立对照预览正常加载原版/修复版页面、Claude 睡眠立绘及特效。预览未加载 CrossPet 外壳，也没有接入 AI。

## 本地验收和限制

本次没有在 macOS 15.8 的原版 WKWebView 快照中稳定重现录屏里的单帧错位。该现象与新时钟周期高度吻合，但不能将具体 WebKit 绘制原因视为已证实。当前修复已移除疑似触发路径，并有确定的暂停/恢复回归证据；仍需在原录屏环境对照验收后再决定上游 PR。

本地生成的 `build/CrossPet Animation Preview.app` 可双击，左右显示原版与修复版睡眠动画，并直接进入休息状态；关闭窗口即退出。它使用独立 Bundle ID，没有安装、AI 接入和后台轮询。

`build/CrossPet.app` 和 `build/CrossPet-macOS.zip` 是完整修复包，只完成构建与签名校验，没有安装或启动。完整 App 启动会同步用户资源并检查既有接入；需要实际替换现有安装时再单独安排。

Windows 共用的网页逻辑已修改，但未在 WebView2 或 Windows 真机验证；Intel 仅编译，未做真机运行验证。活动期间功耗、原录屏环境的视觉验收和完整外壳运行验收尚未完成。

## 跨姿态及原生窗口可见性补测

用户进一步观察到：切换桌面后，思考/加载特效也会跳变；再次切换有时恢复。因此问题范围应按可见性恢复后的 SVG 时钟/绘制异常考虑，不能仅归因于睡眠 5 FPS。已有修复对所有 `#fx` / `#cards` SVG 生效。

测试窗口补上与正式桌宠相同的 NSPanel 可见性通知路径和 `.canJoinAllSpaces` / `.stationary` 标志，通过 `orderOut` / `orderFrontRegardless` 触发真实 AppKit 隐藏/恢复，覆盖 sleeping、thinking、running。空立绘夹具使用固定底色，避免完全透明的测试内容本身引发可见性变化。

最终相同夹具下，原版 17 项检查中 8 项通过、9 项失败；三种姿态在原生隐藏约 0.6 秒后恢复，SVG 时间均跨过约 0.64 秒。修复版 17 项检查通过。在三种姿态的原生隐藏/恢复回调中，SVG 时间差均小于 0.001 秒；恢复使用原生播放，不再跨过隐藏时段。该测试验证原生窗口可见性桥接与时钟，不等价于实际 Spaces 手势和逐帧视觉验收；本次没有自动切换用户桌面。

本地对照预览已增加思考/加载、运行、阅读选择，并接上原生窗口可见性回调和跨桌面窗口标志。它仍没有完整桌宠的 AI 跟随/角色切换逻辑。旧预览需关闭后重新打开，才能使用更新。

“切换后有时恢复”的具体机制尚未证明。需要区分恢复时是否发生姿态/角色改变和 SVG 替换，还是在完全不改变姿态的情况下仅等待循环后恢复。

## 实际 Spaces 手势录屏对照

用户随后提供本地 `recreate.mov`（19.12 秒、1260×996、约 60 FPS），录制独立对照预览，左侧为原版手动 SVG 时钟、右侧为修复后的原生播放。先选择睡眠、思考，再切到运行，随后多次左右切换桌面；运行姿态在后半段保持不变。

桌面切换后，左侧运行特效出现持续的文字闪跳。按解码帧的实际 PTS，16.866667 秒左侧三行文字完整，16.883333 秒第二、三行突然消失，16.900000 秒又完整恢复；右侧对应三帧三行均保持完整。该特效设计为 3 秒循环、分阶段显示三行，不能解释相邻约 16.7 毫秒帧内“完整—消失—完整”的反复倒退。帧序号和时间不能简单用名义 FPS 相除，本文使用视频实际时间戳。

这补上了实际 Spaces 操作下的视觉对照证据：相同录屏、窗口、姿态和桌面操作中，原版出现异常而候选修复避免了这一段异常。结合原生可见性回归测试，证据支持桌面切换暴露原版手动 seek 路径的绘制问题。录屏本身没有同步记录 SVG 内部时间或 WebKit 调度，因此仍不能断言某个具体 WebKit 内部机制；也未验证完整桌宠外壳、长期稳定性和功耗。

原始录屏及仅含动画终端的相邻帧裁图留在本地，未提交到仓库。本节更新此前“没有稳定视觉复现”的验收状态；候选产品代码没有因为本次录屏再修改。
