# macOS 应用生命周期绑定

设置 →「其他」→「跟随应用退出」，可选「不绑定（默认）」或一个正在运行的桌面应用。先打开应用，再打开设置；列表按应用的 bundle identifier 保存选择，不保存安装路径。以 Codex 为例，选择其桌面应用后，只要它的任意实例仍在运行，桌宠就保持运行，与其他 AI 是否退出无关。

该选项只决定桌宠何时退出，工作姿态仍由原有 AI 接入传递。启动方式也保持原有行为：手动打开、登录启动，或接入后的 AI 工作事件触发；仅打开宿主窗口不会额外启动桌宠。关闭窗口、切到后台或最小化不等于完全退出应用。

- 默认不绑定，保留原有退出行为。
- 绑定应用的最后一个进程完全退出后，桌宠退出；多个实例会等待最后一个。
- 保存了绑定但宿主未运行时，桌宠在启动时退出。可先打开宿主，再启动桌宠并在设置中取消绑定。
- 选择新绑定时要求该应用已经运行；如果它已退出，保留原选择并提示重新打开应用。
- 更换或取消绑定会移除旧通知观察者。与前台角色切换、工作事件、登录启动均为独立设置。

实现使用 `NSWorkspace` 的应用退出通知，并在现有状态轮询中检查，没有新增计时器、LaunchAgent、后台监控程序或钩子配置。查询应用列表短暂丢失时，保留此前见过并经内核核对的 PID / 可执行文件路径，直到进程消失或路径改变。生命周期检查只在选项开启时执行；未测量真实宿主长期运行时此检查的单独开销。

边界：这是 macOS 桌面应用绑定，不适用于没有 bundle identifier 的命令行 agent；Windows 宿主隐藏此设置。宿主重新启动与退出紧邻发生时，桌宠可能在新实例注册前先退出，之后仍依靠现有工作事件或手动启动。宿主关闭与桌宠退出并非同步操作，通常由通知或下一次状态轮询检测（取决于运行模式，名义间隔为 0.3–1 秒）；系统调度可能延后。没有新增生命周期日志，也不发送应用列表或进程路径。
